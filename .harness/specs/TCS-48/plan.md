## ASSUMPTIONS
- Ambiguous: scope 1 says "LIMIT 100, the same read as the page" and also "the response shape is unchanged". The current shape is ONE advisory object. Assumed: the route keeps one advisory object, the earliest by `cursor` among all advisories that list the CVE in any `cve_ids` entry. It reuses `ADVISORIES_BY_CVE_SQL` from `src/routes/advisory.ts` and binds the limit to 1, because the route reads only the first row. Other reading: return an array of up to 100 advisories. That breaks the shape, the MCP tool and the CLI, so it was not chosen.
- Ambiguous: scope 2 says docs must say "returns every advisory that lists the CVE". With one object, the docs say: "The earliest advisory (by feed cursor) that lists the CVE id in any of its `cve_ids`, not only the first. `/cve/{cve}` with `Accept: application/json` lists all of them." Other reading: the literal "returns every advisory". That would describe a shape the route does not return.
- Ambiguous: the `LIMIT` bind of 1 is a literal. It is the response shape (one object), not a tunable cap, so it is not a knob under BH-7945. The comment at the bind says so. Other reading: bind `CVE_PAGE_CAP` and take the first row. That reads up to 100 rows to return 1.
- No `cve_primary` fallback in the route. The ingest invariant above makes it dead code in prod. The existing test gets its `advisory_cves` row instead.

## Iron laws
- Additive schema: no migration. The table and its primary key exist (migration 0010).
- Indexes: the read uses the `advisory_cves` primary key and the `advisories` primary key. T2 proves it with EXPLAIN on 2,000 seeded rows. No correlated subquery.
- Retention: no new table. `advisory_cves` retention is already in `docs/RETENTION.md` (not touched).
- DB-driven config: no new limit. The bind of 1 is the response shape (see ASSUMPTIONS).
- Metered calls / dedup-before-spend: none. No vendor call. No LLM. No De-AI surface.
- UI rules (sortable headers, list over cards, drill-down): n/a, JSON route only.
- Feed reads cheap: one indexed read, at most 1 row returned.

## Performance
- Reads: 1 D1 statement per request (unchanged count). Rate limiter reads are unchanged.
- Parallel reads: n/a (one read).
- Indexes: `sqlite_autoindex_advisory_cves_1 (cve, advisory_id)`, then `sqlite_autoindex_advisories_1 (id)`. A temp B-tree sorts the rows of one CVE by cursor; that set is one row per affected package.
- Loading skeleton: n/a (JSON API).
