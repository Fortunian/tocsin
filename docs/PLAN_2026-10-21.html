Why now

What happened on 2026-10-21

PHP shipped fixes for two remote code execution flaws, CVE-2026-109618 and CVE-2026-109619, both scored 9.2, in 8.5.12, 8.4.27, 8.3.36 and 8.2.35. PHP said there is no workaround. The FBI told operators to take unpatched servers offline. PHP 8.1 and older get no fix.

Node.js fixed 10 flaws the same day, four high. CVE-2026-111497 is an out-of-bounds write in the Brotli decoder, reachable through fetch() when a server replies with Content-Encoding: br. Fixed in 22.23.4, 24.22.1 and 26.12.1.

Why agents need their own feed

Agents run on these runtimes and call these packages. Today the advisory exists as a blog post, an RSS item, an NVD record and an OSV record, in four shapes, none of which says "upgrade node to 24.22.1". An agent cannot subscribe to a blog post.

Nothing in the market serves agents first. ClawSec covers two agent frameworks. VulnFeed is an MCP wrapper over NVD with no runtime coverage and no "am I affected". OSV is a package database, not a runtime feed, and has no push.

Product

An advisory is one normalized record with the fields an agent needs to act: ecosystem, component, affected ranges, fixed versions, severity, whether it is exploited in the wild, a one-line summary and a one-line action. Every advisory carries a monotonic cursor, so a consumer asks for "everything since my last cursor" and never misses or repeats an event.

curl "https://tocsin.sh/v1/events?since=0&ecosystem=node,npm&min_severity=high"

Feed

GET /v1/events with since, ecosystem, component, severity and exploited filters. Page cap 100. ETag and 304 so polling costs nothing.

Check

POST /v1/check with a lockfile or runtime versions returns the affected list with fixed_in. This is the feature an agent uses at session start and before a deploy.

Watch lists

A saved filter with its own cursor. GET /v1/watchlists/:id/events advances the cursor, so a polling agent keeps no state.

Webhooks

Pro. Signed POST per event, exactly-once on (watch list, advisory), five retries with backoff, delivery history.

MCP

mcp.tocsin.sh with tools tocsin_latest, tocsin_check, tocsin_get. One config block for Claude Code, Cursor and Claude Desktop.

CLI + skill

npx tocsin check reads lockfiles and runtime versions in the current directory and exits 1 when anything is affected. The skill tells Claude Code when to run it.

Architecture

Sources

OSV API, nodejs.org security posts + dist index, php.net releases, NVD 2.0, CISA KEV, EPSS CSV
→

Ingest (cron, 10 min)

One ingester per source, registry in DB. Idempotent upsert on (source, source_id). Cross-source merge by CVE. Cursor in KV, advanced only after a full page.
→

D1

advisories (doc_json + indexed columns + cursor), advisory_sources, sources, api_keys, plans, watchlists, deliveries
→

Serve (Hono worker)

/v1/events, /v1/check, /v1/watchlists, well-known, llms.txt, site, status. ETag + rate limit in KV.
→

Push

Queue consumer signs and POSTs webhooks. deliveries row is the exactly-once gate.

Design rules

  • Additive-only schema. Indexes and a retention rule ship with every table, proved with EXPLAIN QUERY PLAN in tests.
  • Deterministic before LLM. Summary and action come from fixed versions and the source text. No model call in v1.
  • Dedup before spend. NVD is queried only for CVEs with no score and not queried in 24 hours.
  • Limits and plans are DB rows (plans, sources). No constants for live config.
  • One shared seam per vendor in tests (fetch mock, Stripe mock). No external service in the PR test path.

Cost at idle

Workers free tier covers 100,000 requests a day. D1 free tier covers 5 million row reads a day. Six cron runs an hour fetch a few hundred KB. The service runs at $0 until it has paying users, then on the $5 Workers Paid plan.

No LLM cost, no database server, no container. The open-source self-host story is "wrangler deploy".

Discovery for agents

An agent that lands on tocsin.sh must get everything from two files. /.well-known/tocsin.json lists the schema URL, the endpoints and the MCP URL. /llms.txt is the plain-text guide: the curl line, the cursor rule, the check endpoint, the MCP config. The schema is served at /schema/advisory.v1.json and versioned. No sign-up to read.

Tiers and open source

Open source Apache-2.0

Engine, schema, ingesters, MCP server, CLI, skill. Self-host with one wrangler deploy. The schema is the standard we want others to adopt, so it stays open and versioned.

Risks

RiskMitigation
A runtime vendor changes its blog or release page format and the ingester silently emits nothing.Each ingester records last_ok_at. The status page and a daily check alert when a source has not produced a row in 7 days. Fixtures are recorded HTML, so a format change fails a test on the next PR too.
Wrong fixed versions published to agents that act on them.Fixed versions come only from the vendor post, cross-checked against the dist index where one exists. Every advisory links its source. The schema has no free-text field that an ingester invents.
Version range matching errors (PEP 440, composer, pseudo-versions).Table-driven tests per ecosystem with boundary cases. The check response says "checked n" so a consumer sees coverage, not only hits.
Free tier abuse of the check endpoint.Per-IP KV rate limit, 2 MB body cap, batched candidate queries with an index proof.
Name collisions: tocsin.ai, tocsin.io, tocsin.dev are owned by others.The brand is "Tocsin" at tocsin.sh, npm tocsin, PyPI tocsin. GitHub user tocsin is taken, so the repo is Fortunian/tocsin.
